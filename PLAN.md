# Kompot Vote — план

Внутренняя страница, на которой команда (10–11 участников) голосует, какие импро-форматы играть на шоу (≈ 1,5 часа).

Структура шоу: **Конферанс → Слот 1 → Слот 2**. Это может быть короткая разминка или скетчи, а потом история. Или две длинные истории. Или один формат на весь вечер.

---

## 1. Хостинг

**GitHub Pages** бесплатно раздаёт статичную страницу по ссылке вида `nook2b.github.io/kompot-vote`. Под страницу это подходит идеально. Хранить голоса GitHub Pages не умеет: это просто файлы, без сервера и базы. Поэтому для данных нужно что-то маленькое бесплатное:

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **А. GitHub Pages + Supabase** (рекомендуется) | Страница на GitHub, голоса в бесплатной базе Supabase | Обновления в реальном времени. Коды и лимиты проверяются на сервере, обойти нельзя | Нужно один раз завести аккаунт Supabase (около 5 минут) |
| **Б. GitHub Pages + Google Таблица** | Голоса пишутся в Google Таблицу через Apps Script | Все голоса и коды видно в таблице | Страница обновляется раз в несколько секунд. Настройка менее удобная |
| **В. Только GitHub** (голоса как коммиты или issues) | — | — | Ключ доступа пришлось бы класть прямо в страницу, его может забрать кто угодно. Не подходит |

**Важно:** бесплатный GitHub Pages работает только для **публичного** репозитория (для приватного нужен GitHub Pro). В репозитории лежат только код и описания форматов. Коды участников туда не попадают: они хранятся в базе в зашифрованном виде.

## 2. Вход по одноразовым кодам

- На каждого участника заводится код, привязанный к имени: Маша → `K7P2`, Лёша → `M9X4` и так далее. Плюс отдельный код админа.
- Каждому рассылается **личная ссылка** `…/kompot-vote/?code=K7P2`. По ней человек входит в один тап. Если ссылка потеряется, код можно ввести вручную.
- После входа телефон запоминает участника. За кодом закреплён ровно один голос в каждом раунде.
- Админ может перевыпустить код, например если ссылку переслали не тому.

## 3. Механика голосования

### Выбранная схема: «сначала форматы, потом программа»

- **Раунд 1, выбор форматов.** Список карточек. Каждый участник отдаёт 3 голоса за 3 **разных** формата. После голоса он сразу видит общий результат. Топ-3 проходят во второй раунд.
- **Раунд 2, сборка шоу.** Голосуют только те, кто голосовал в первом раунде. На экране таймлайн **[Конферанс] → [Слот 1] → [Слот 2]** и 3 финалиста. Финалистов перетаскивают в слоты. Один формат можно поставить в оба слота («две истории X»).
- **Итог.** По каждому слоту отдельно побеждает формат, который туда ставили чаще всего. Получается программа: «Начало: A, конец: B» или «оба слота: X».

Плюс: голоса не размазываются, у каждого слота есть явный победитель. Минус: слоты считаются независимо, поэтому теоретически сочетание A + B может не быть ничьим любимым.

### Альтернативы (на случай, если захочется поменять)

- **Голосуем сразу за программы.** Каждый собирает шоу целиком (слот 1 + слот 2) и может предложить до 3 программ. Топ-3 проходят во второй раунд. При 11 людях и 10+ форматах голоса рассыпаются по сотням комбинаций, будет много ничьих. Не рекомендуется.
- **Каждый раунд по слотам.** Уже в раунде 1 голоса раскладываются по слотам. Получается два параллельных мини-голосования: точнее, но сложнее и дольше.

### Ничьи

Если за третье место ничья, админ выбирает, кто проходит, или проходят все поделившие. Это решается в админке.

## 4. Таймлайн шоу

- Горизонтальная полоса на 90 минут: **Конферанс → Слот 1 → Слот 2**. Ширина блока пропорциональна длительности.
- Если форматы не влезают в 1,5 часа, полоса подсвечивается и показывает, на сколько вышли за время.
- Перетаскивание с запасным способом для телефона: тапнул формат, тапнул слот.
- После раунда 2 на том же таймлайне показывается итоговая программа.

## 5. Экраны

1. **Вход** по коду или личной ссылке.
2. **Раунд 1.** Карточки форматов. Кратко: название, суть одной строкой, тип, длительность. По нажатию карточка раскрывается и показывает, как формат играется. 3 голоса. После голосования результаты в реальном времени и счётчик «проголосовало 7 из 11».
3. **Раунд 2.** Таймлайн с перетаскиванием финалистов. После голоса результаты по каждому слоту.
4. **Итог.** Финальная программа на таймлайне.
5. **Админка** (вход по коду админа):
   - кто проголосовал, а кто нет, по именам;
   - кнопки «Закрыть раунд 1 → раунд 2» и «Закрыть раунд 2 → итог»;
   - решение ничьих;
   - сброс для следующего голосования, перевыпуск кодов, правка списка форматов.

Экран для проектора не нужен.

## 6. Технически

- **Фронтенд:** одна лёгкая мобильная страница (Vite + React), деплой на GitHub Pages через GitHub Actions.
- **Бэкенд (вариант А):** Supabase. Таблицы `formats`, `participants` (имя + хеш кода), `votes` (участник, раунд, формат, слот), `show_state` (текущий раунд, финалисты).
- **Правила на сервере:** в раунде 1 ровно 3 разных формата. В раунде 2 по одному голосу на слот и только за финалистов. Второй раунд доступен только тем, кто голосовал в первом.

## 7. Этапы работы

1. Каркас страницы и деплой на GitHub Pages с тестовой ссылкой.
2. Подключение Supabase: таблицы, проверка кодов, ограничения на голоса.
3. Вход по коду и личной ссылке.
4. Раунд 1: карточки, 3 голоса, результаты.
5. Админка и переключение раундов.
6. Раунд 2: таймлайн, перетаскивание, подсчёт по слотам.
7. Итоговый экран.
8. Оформление: логотип, цвета, русский язык.
9. Проверка на iPhone и Android. Прогон на тестовых кодах.

## 8. Что нужно от владельца

**Чтобы начать:**
1. Подтвердить механику (рекомендуется схема из раздела 3).
2. Выбрать хостинг: А (Supabase) или Б (Google Таблица). Подтвердить, что репозиторий можно сделать публичным.
3. Прислать список форматов по шаблону из [FORMATS_BRIEF.md](FORMATS_BRIEF.md).

**Чуть позже:**

4. Имена участников (10–11 человек) для кодов.
5. Конферанс: фиксированный ли это блок и сколько минут он занимает. Есть ли другие фиксированные части (антракт, поклон).
6. Анонимность: видно ли всем, кто за что голосовал, или только общие цифры.
7. Логотип и, если есть, цвета.
8. Supabase (если выбран вариант А): создать бесплатный проект по инструкции и передать адрес проекта и публичный ключ.
9. GitHub Pages: включить в Settings → Pages по инструкции.
